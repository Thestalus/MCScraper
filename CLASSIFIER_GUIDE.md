> **Reading the numbers in this guide.** Scores here come from different kinds of evidence — LLM-adjudicated audits, Svengali agreement, out-of-fold (OOF) cross-validation — and are not interchangeable; see [Evidence terms](ARCHITECTURE.md#evidence-terms). OOF F1 figures from before 2026-10-03 are optimistic: the SetFit encoder was fine-tuned on the same stories they were measured on. ## FP Audit — Full Results (March 2026)

### What the FP audit is

The false-positive audit (`fp_audit_auto_review.py`) measures the **true precision** of
`auto_tags` by having Claude Haiku review candidate false positives — stories that were
auto-tagged but are **not** in their Svengali raw tags. Svengali undertags heavily, so
many "FPs" by the Svengali metric are actually correct tags. The LLM reviewer determines
which ones are genuine errors vs. correct tags Svengali missed.

**Formula:**  `precision = TP / (TP + FP)`  where AMBIGUOUS is excluded from both counts.

**Margin of error:** ±13 pp at n=50, ±9 pp at n=100.

### How to run the audit

```bash
# Export API key first (must have credit; ~$0.003/story)
export ANTHROPIC_API_KEY="sk-ant-api03-..."

cd ~/Code/MCScraper

# Priority tags only (~$0.50, ~10 min)
python fp_audit_auto_review.py

# All tags (~$6, ~2–3 hours depending on credit)
python fp_audit_auto_review.py --all-tags

# Single tag
python fp_audit_auto_review.py --tag "themes:willing subject"

# Check current results
python3 -c "
import json
from collections import defaultdict
results = defaultdict(lambda: {'TP':0,'FP':0,'AMB':0})
with open('output/fp_audit_results.jsonl') as f:
    for line in f:
        r = json.loads(line)
        tag = r['tag']
        if r['label']=='TRUE_POSITIVE': results[tag]['TP']+=1
        elif r['label']=='FALSE_POSITIVE': results[tag]['FP']+=1
        else: results[tag]['AMB']+=1
for tag,c in sorted(results.items(),key=lambda x:-(x[1]['TP']/(x[1]['TP']+x[1]['FP']) if x[1]['TP']+x[1]['FP']>0 else 0)):
    tp,fp=c['TP'],c['FP']
    n=tp+fp+c['AMB']
    prec=tp/(tp+fp) if tp+fp>0 else 0
    print(f'{prec:.0%}  n={n:3d}  {tag}')
"
```

Results are written to `output/fp_audit_results.jsonl` (append-only, deduplicates on
`(story_id, tag)`). Model: `claude-haiku-4-5-20251001`. Cost: ~$0.00155/story reviewed.

### Rule fixes applied before the March 2026 audit

Four tags were identified as noisy from initial FP sampling and their tagger.py rules
were tightened before the full audit ran:

| Tag | What changed | Why |
|-----|-------------|-----|
| `themes:willing subject` | Replaced broad keyword list with consent-specific phrases (`wanted to be hypnotized`, `chose to submit`, `volunteered`, etc.); min_n kept at 2 | Was firing on post-MC compliance language |
| `awareness:valiant but futile struggle` | Removed passive "no choice / couldn't resist" phrases; kept only active resistance (`mind screamed`, `tried to resist but`, `screamed inside`); raised min_n 1→2 | Was firing on victim states, not active struggle |
| `pacing:rapid` | Raised word-count thresholds: <3k words needs 3 hits, <6k needs 5 hits, else needs 8 hits | 2-hit threshold too low for short stories |
| `pacing:leisurely` | Raised regex min_n 2→4; raised structural density threshold 0.8→1.5 skips/1k words | Was firing on any time-skip in otherwise fast stories |

Even after tightening, all four tags remained under 50% precision (see table below) —
they are strong candidates for **dropping from regex** entirely.

### SetFit vs Regex: key comparison findings

After running the FP audit and analyzing `_tag_sources` per story, the most important finding:

**`mind_control_type:hypnosis`** — regex-alone precision: **25%**; when both regex AND SetFit agree: **89%**. SetFit is not just additive here — it acts as an essential quality gate. Stories that only regex catches (SetFit disagrees) are nearly all FPs.

**`mental_changes:obedience programming`** — both layers strong independently (regex 83%, SetFit 86% at oof_f1=0.727). 94 of 100 audited stories tagged by both.

**`mental_changes:memory alteration`** — regex 67% alone, 91% when both agree. SetFit raises the ceiling.

**`awareness:valiant but futile struggle`** — counterintuitive: the 5 regex-only stories (SetFit disagrees) are **100%** precision, while the 45 "both agree" stories are only 47%. The regex catches genuine struggle language that SetFit misses; SetFit agreement is not a positive signal here.

To apply the AND gate in code:
```python
def is_high_confidence(story, tag):
    sources = story['auto_tags'].get('_tag_sources', {}).get(tag, [])
    return 'regex' in sources and 'setfit' in sources
```

```python
    # Dropped (F1 < 0.30 — classifier fires on too much, hurts more than helps):
    # 'corruption arc' (0.065), 'reluctant subject' (0.052), 'oblivious' (0.043),
    # 'cold / clinical' (0.048), 'horror / dark' (0.027), 'creampie' (0.176)
}

def story_training_tags(story):
    """Return high-confidence tags suitable for LLM training prompts."""
    at = story.get('auto_tags', {})
    sources = at.get('_tag_sources', {})
    result = {}

    # Tier 1: always trust
    for dim, tags in at.items():
        if dim.startswith('_') or dim in ('pov', 'length_class', 'story_status'):
            continue
        for tag in (tags if isinstance(tags, list) else []):
            if tag in TIER_1_TAGS:
                result[tag] = 'high'

    # Structural: always include
    for dim in ('site_tag_groups', 'site_tags_expanded', 'content_type'):
        for tag in at.get(dim, []):
            result[tag] = 'structural'

    # Tier 2: AND gate
    for tag in AND_GATE_TAGS:
        tag_srcs = sources.get(tag, [])
        if 'regex' in tag_srcs and 'setfit' in tag_srcs:
            result[tag] = 'medium'

    return result
```

### Fix: stale embedding cache after Windows fine-tuning

If you re-run SetFit training on a machine where embeddings were already cached
(e.g. from a previous Mac run), `build_embeddings()` will find all stories
already in the cache and skip re-embedding — even though the model was updated.
The classifiers then get trained on the old model's embeddings while
`model.safetensors` reflects the new model. **This silently degrades quality.**

Symptom: micro F1 drops vs previous run on the same device.

Fix:
```bash
# On Windows (Command Prompt)
del output\setfit_embeddings.npz
python setfit_trainer.py --train --skip-finetune

# On Mac/Linux
rm output/setfit_embeddings.npz
python setfit_trainer.py --train --skip-finetune
```

`--skip-finetune` reuses the already-trained model weights but forces
re-embedding all stories from scratch. After that, run `--eval` to verify results.

## Why Tags Matter

```
auto_tags
   │
   ├──▶ browser.py search & filtering   (what stories you can find)
   ├──▶ recommender.py                  (what stories you get suggested)
   ├──▶ train.py / LLM fine-tuning      (what the model learns to like)
   └──▶ preference system               (how user taste is modelled)
```

A false positive (wrong tag) pollutes recommendations and filter results.
A false negative (missed tag) makes stories invisible to users who'd love them.
This is why precision AND recall both matter, and why Svengali community
data is used as the benchmark rather than hand-written rules alone.

## Tag Schema

Each story carries an `auto_tags` dict inside `stories_index.json`:

```json
{
  "auto_tags": {
    "mind_control_type": ["hypnosis", "psionic"],
    "dominance":         ["gradual", "gentle"],
    "mental_changes":    ["obedience programming", "memory alteration"],
    "awareness":         ["consensual", "playing along"],
    "pacing":            ["leisurely"],
    "themes":            ["romance", "found family"],
    "tone":              ["dark"],
    "setting":           ["office"],

    "_svengali_tags":    ["mc", "hm", "fd", "ma"],
    "_tag_sources": {
      "hypnosis":             ["regex", "setfit"],
      "obedience programming":["setfit"],
      "romance":              ["regex"]
    }
  }
}
```

**`_svengali_tags`** — raw community tags from the Svengali voting system.
Never overwritten by the tagger; imported separately via `svengali.py --import`.

**`_tag_sources`** — records which layer(s) contributed each tag.
Used by `eval_tagger.py` to isolate regex precision/recall from ML precision/recall.

## Three-Layer Architecture

Tags are computed in three passes, each adding to (never replacing) prior work:

### Layer 1 — Regex (`tagger.py`, ~8 min parallel)

Pattern matching against `title + description + categories + full_text`.
High precision on unambiguous signals (e.g. category code `mc`, keyword `hypno`).
Poor recall on nuanced or implicit content.

Key design decisions:
- **Full-text matching**: all patterns run on the complete story text.
  Early versions sampled chapters; switched to full text March 2026 after
  benchmarking showed only 3× slowdown but nearly double the recall on
  sexual_acts tags (79% vs 38%).
- **`re.DOTALL`**: patterns compile with `re.IGNORECASE | re.DOTALL` so `.`
  matches newlines. Critical for prose where acts span line breaks within
  a sentence.
- **Contradiction suppression**: after all patterns fire, logically incompatible
  tags are removed (e.g. `loving control` is suppressed if `betrayal` or
  `horror / dark` or `slave mentality` are also present).
- **`_tag_sources` recording**: every tag fired by regex is noted as `["regex"]`.

To retag all stories in parallel (10 cores, ~8 min):
```bash
python retag_parallel.py
```

### Layer 2 — Semantic (`tagger.py --semantic`, ~30 minutes)

`sentence-transformers` encodes the story's title+desc+opening and computes
cosine similarity to hand-written label phrases. Falls back gracefully if no
embedding model is installed. Useful for tone and setting inference, less
reliable for specific MC mechanics.

### Layer 3 — ML Classifier (SetFit, ~2 minutes)

SetFit-fine-tuned sentence transformer (`output/setfit_model/`) + per-tag logistic
regression classifiers (`output/setfit_classifiers.pkl`). Covers 26 (dimension, tag)
pairs that regex systematically under-fires on (see Active SetFit models table above).

Each classifier has an **auto-calibrated threshold** computed from out-of-fold
predictions during training — so each tag fires at the probability that
maximises its F1 on training data, rather than a global constant.

Tags from this layer are recorded as `"setfit"` in `_tag_sources`.

To apply classifiers to all stories (~2 min):
```bash
make tag-setfit
# or
python setfit_trainer.py --tag
```

## Svengali as Ground Truth

`svengali.py` fetches community-voted tags from the Svengali project and
imports them into `_svengali_tags`. These votes represent hundreds of readers'
assessments of each story — much richer signal than any automated system.

**Import pipeline:**
```
python svengali.py --import --index output/stories_index.json
```
This merges raw Svengali tag lists into `_svengali_tags` without touching
any other `auto_tags` fields.

**Critical:** `tagger.py` preserves `_svengali_tags` on every re-run.
Do not manually replace `auto_tags` — always use `process_index()` which
saves and restores the Svengali data.

**Coverage:** ~14,800 of ~17,600 stories have Svengali tags (as of March 2026).
Stories without Svengali tags are still tagged by regex and ML, but cannot
be evaluated for precision/recall.

### Svengali systematically undertags — measured precision is pessimistic

Svengali tags are added by community vote, so a story only gets a tag if enough
readers specifically nominated it. Many clearly-matching stories are simply never
voted on. This means the "false positives" reported by `eval_tagger.py` and
`retrain_classifiers.py --eval` are largely **real stories that Svengali missed**,
not actual classifier errors.

**Evidence from March 2026 FP sampling:**

| Tag | Sample finding |
|-----|---------------|
| `obedience programming` | `ObedienceIsAQuietRoom` — Svengali lists `Operant Conditioning` under its tags but no `ob` tag; `Obedient` = "Everyone has to do what Sophie says" — no `ob` tag |
| `addiction/need` | Top 20 FPs were all unambiguous chemical-addiction stories that Svengali simply hadn't tagged |
| `gentle` | Soft hypnosis induction stories that matched the pattern clearly; Svengali `Gentle` tag not applied |
| `denial` | Entire "Darke" series episodes — consistent denial theme throughout the series, inconsistently tagged |

**Practical rule:** before concluding a tag is broken, always manually sample
20–30 "false positives":
```bash
python eval_tagger.py --examples <tag>   # shows FP stories with titles/descriptions
```
If most FPs look like real matches, the measured F1 is pessimistic and the
pattern/classifier is likely working. Only tighten patterns when FPs are
genuinely wrong (unrelated stories triggering on common vocabulary).

> **Note:** The frozen-embedding approach (`sv_classifier.py`, `make train-sv-clf`) was

| Setting | Value |
|---------|-------|
| Encoder | `all-mpnet-base-v2` fine-tuned via SetFit contrastive learning |

### What the eval output means

```

obedience programming            0.730    0.58        37%
pacing:leisurely                 0.625    0.52        9%
hypnosis                         0.596    0.61        33%
```

## Current Approach (March 2026)

### Why the frozen-embedding classifier failed

The first full training run used `all-mpnet-base-v2` + per-tag logistic
regression with auto-calibrated thresholds. Results on the 27-tag multi-label
problem were disappointing:

| Metric | Result | Expected |
|--------|--------|---------|
| Micro precision | 12% | 50–70% |
| Micro recall | 83% | 50–70% |
| Micro F1 | 0.202 | 0.50+ |
| Only usable tag | `hypnosis` at F1=0.502 | — |

**Root cause:** frozen general-purpose embeddings compress all stories into a
generic semantic space. Genre-specific vocabulary — "played along", "induced
love", "valiant but futile struggle" — lands at similar embedding positions to
many unrelated stories. The classifier compensates by lowering thresholds
(boosting recall) but precision collapses.

### What we are doing now: SetFit fine-tuning

**SetFit** (Sentence Fine-Tuning) adapts the embedding model itself before
training classifiers. It generates positive/negative contrastive pairs from
Svengali labels, then fine-tunes the sentence transformer so that stories
sharing the same tags end up closer together in embedding space.

After fine-tuning, new embeddings are computed for all stories (multi-chunk
max-pooling: 5 windows, element-wise max), and per-tag logistic regressors are
trained as usual.

**Why SetFit over the alternatives:**
- Faster and cheaper than full LLM classification (17k stories × 55 tags would
  take days with any local LLM)
- Reuses the same logistic-regression + calibration pipeline
- Purpose-built multi-label support via `multi_target_strategy="one-vs-rest"`
- Contrastive training is highly sample-efficient with noisy Svengali labels

### Lessons learned from the March 2026 regex audit

**Svengali precision measurements are pessimistic.**
Most "false positives" from regex patterns are real acts/attributes that Svengali
didn't tag, not actual errors. Measured precision of 18–24% on sexual_acts
likely reflects 60–70% true precision. Always manually sample FPs before
deciding a pattern is broken.

**Curly apostrophe bug (fixed March 2026).**
Story text uses curly apostrophes (U+2019: `'`) while regex patterns were
compiled with straight apostrophes (`'`). Contractions like `couldn't`,
`won't`, `can't` in patterns silently never matched. Fixed by:
1. Normalizing the corpus in `regex_tag()` with `.replace('\u2019', "'")`
2. Also normalizing in `_r()` so patterns can be typed with either apostrophe type

Side effect of the fix: tags with contraction-heavy patterns (`body puppet`:
`couldn't control arm/leg`, `possession`: `no longer herself/himself`) now
fire on dramatically more stories. After the fix, `body puppet` went from
926 → 10,529 auto-tagged and `possession` from 863 → 6,975 — both due to
unbounded `.*` with `re.DOTALL` matching across thousands of characters.

Fixed in March 2026 by replacing unbounded patterns with `.{0,N}` bounded
alternatives requiring explicit body/mind context. Final counts after fix:
**body puppet: 1,021** auto-tagged, **possession: 690** auto-tagged.
Regex eval F1: body puppet=0.13, possession=0.10 (most coverage comes from
SetFit: F1=0.603 and 0.583 respectively).

**Awareness tags were broken before March 2026.**
All AWARENESS_RULES patterns showed 0 auto-tagged stories because:
a) the curly apostrophe bug prevented contraction patterns from matching, AND
b) `retag_parallel.py` didn't update `_tag_sources`, so eval couldn't see results

Both are now fixed. `playing along` and `skeptical / confused` dropped from
regex — they require full narrative arc understanding and are left to SetFit.

**`_tag_sources` must be kept current.**
The eval (`eval_tagger.py`) uses `_tag_sources` to identify which tags came
from regex. `retag_parallel.py` **rebuilds** `_tag_sources` for regex from scratch
on every run — it strips all old `"regex"` entries first, then re-adds only for
tags that currently fire. This prevents stale regex sources from falsely satisfying
the AND-gate for patterns that were later removed or tightened.
If you run `tagger.py` directly (not via retag_parallel), `_tag_sources` is
updated by `process_index()` which handles it correctly.

**Tags best left to ML (too context-dependent for regex):**
`gentle`, `gradual`, `subtle`, `speedy` dominance; `rapid`, `epic` pacing;
`personality removal`, `purification`, `body puppet`, `possession`,
`operant conditioning` MC type; `romance`, `slow burn`, `consent/ethics` themes;
`emotion control`, `induced love` mental changes; all `prevalence` tags;
`tone` tags except `humorous/playful`. These use vocabulary so common in MC
fiction that even high min_n thresholds give very high FP rates.

**Over-broad tag audit (March 2026).**
After running `eval_tagger.py` post-regex-fix, several tags were found to have
F1 < 0.16 with auto counts in the thousands — meaning the patterns were firing
on almost everything. These were removed from `tagger.py` entirely and left to
SetFit: `gradual` (7,406 auto, F1=0.15), `personality removal` (6,907, F1=0.10),
`operant conditioning` (6,696, F1=0.16), `subtle` (3,715, F1=0.16),
`purification` (6,057 auto, only 24 Svengali examples). `orgasm control` was
kept but tightened to require explicit permission/denial language
("don't cum without permission", "only cum when I say") — auto count dropped
8,270 → 1,258, F1 improved 0.18 → 0.24.

## Improvement Ladder

When classifier quality is insufficient, these steps address different root
causes. Work through them in order — each builds on the previous.

### Step 1 — Multi-chunk pooling

**Root cause addressed:** long stories (50k+ words) compressed to one
embedding miss signals in individual chapters.

**Implementation:** embed 5 fixed windows per story (head / early / mid /
late / tail), then `np.max(chunks, axis=0)` before classification. Max-pooling
asks "does ANY window activate this feature" — right for tags like `brutal`
or `memory alteration` that appear in one scene.

**Effort:** ~2 hours compute; code changes in `story_chunks()` and
`build_embeddings()`. New cache file ~250MB.

**Best for:** scene-specific tags: `brutal`, `memory alteration`, `betrayal`,
`addiction/need`, `twist` endings.

### Step 2 — SetFit fine-tuning ✓ IN PROGRESS

**Root cause addressed:** frozen general-purpose embeddings don't understand
genre-specific vocabulary and tropes.

**Implementation:** [SetFit](https://github.com/huggingface/setfit) fine-tunes
the sentence transformer itself using contrastive learning on positive/negative
pairs from Svengali labels. Supports 55-tag multi-label in one training run
via `multi_target_strategy="one-vs-rest"`.

```bash
pip install setfit transformers==4.57.6
python setfit_trainer.py   # trains, embeds, classifies, calibrates
```

**Note:** `transformers` must be pinned to `4.57.6` — version 5.x breaks setfit
1.1.3 with `ImportError: cannot import name 'default_logdir'`.

**Status:** Training completed March 2026. See "Current Approach" section above.
**Expected gain:** +15–25% F1 over frozen embeddings on domain-specific tags.

**Best for:** tags requiring genre knowledge: `playing along`, `denial`,
`valiant but futile struggle`, `induced love`, and the new sexual_acts /
relationship dimensions.

### Step 3 — Active learning (highest ROI)

**Root cause addressed:** Svengali labels have noise (inconsistent community
voting). Training on noisy labels limits every model.

**Implementation:**
1. Run classifiers at medium confidence (0.40–0.65) — the uncertain zone
2. Export ~100–200 borderline stories per tag: title, description, opening
   300 words, predicted tag, confidence score
3. Review and mark correct / wrong (~5–10 min per tag)
4. Merge corrections into training data, retrain
5. Repeat once or twice on worst tags

```bash
python review_labels.py --tag "body_puppet"    # to be written when needed
```

**Effort:** mainly your time — ~1 hour of reading to clean the 5 worst tags.
**Expected gain:** often more improvement than any model change because it
fixes the data quality problem at the source.

**Best for:** tags that classifiers consistently struggle with despite
adequate training size: `body puppet`, `possession`, `addiction/need`, `pacing: epic`.

### Step 4 — LLM verification (after SetFit)

**Root cause addressed:** some tags require full story comprehension that
embedding models approximate but LLMs handle directly.

**Implementation:** run the best classifier at low threshold (0.35) to
generate candidates, then send only borderline stories (~10–15% of total)
to Claude with a focused binary prompt. This avoids the cost of classifying
all 17k stories with an LLM.

**Dependencies:** do this after SetFit so the LLM is reviewing genuinely
uncertain cases, not drowning in easy false positives.

**Best for:** tags that require understanding story arc and intent rather
than surface vocabulary: `subtle` dominance, `playing along`, narrative twists.

## LLM Full-Corpus Tagging Plan (Claude Haiku API)

### Rationale

Regex and SetFit cover concrete, keyword-definable mechanics well (hypnosis, obedience programming,
sexual acts, etc.). They fail systematically on anything requiring narrative-level comprehension:
pacing, tone, relationship dynamics, prevalence scope, and thematic arcs. These are exactly the
dimensions readers use to choose stories. An LLM tagging pass fills this gap at acceptable cost.

### Cost and timing estimates

| Model | Per-story input | Per-story output | Total (18,282 stories) | Batch API (50% off) |
|-------|----------------|-----------------|------------------------|---------------------|
| Haiku 4.5 | ~10,000 tok | ~400 tok | ~$175 | **~$87** |
| Sonnet 4.6 | ~10,000 tok | ~400 tok | ~$660 | ~$330 |

**Recommendation: Haiku 4.5 with Batch API.** Reliable JSON output, no VRAM constraints,
no chunking needed (200K context window handles even the longest stories in one pass),
completes in hours rather than 8 days.

Average input assumes full story text + prompt/schema overhead. Longer stories raise this;
most (73%) are ≤10K words so the average is stable.

### Which tags to request

Since output tokens cost almost nothing relative to the story text input, there is no reason
to limit the schema to gap-filling tags. Ask for everything — existing regex/SetFit tags
included. This gives a second signal for AND-gating, catches cases regex/SetFit missed, and
produces a single authoritative LLM pass rather than a patchwork.

**Do NOT include**: structural/Svengali-derived tags (`site_tag_groups`, `site_tags_expanded`,
`content_type`, `pov`, `length_class`) — these come from metadata, not story analysis.
